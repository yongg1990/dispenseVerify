# 两份附件合并需求

## 依据与优先级

附件 1 `PDA_Pharmacy_Home_Search.html` 提供工作台布局、门诊 / 住院业务切换、四个入口、处方摘要与操作弹窗的参考。

附件 2 `控制台.txt` 是业务要求及沟通中的问题清单。明确业务结论优先于原型；问句和部署疑问保留为待确认项，不擅自视为已确认结论。

## 已落实到本地演示的规则

| 模块 | 合并后的要求与处理 |
| --- | --- |
| 工作台 | 门诊 / 住院业务独立数据，药包验收、患者发药、验收明细、发药明细四个独立页面入口 |
| 门诊流程 | 药房验收及发药；扫描就诊码识别患者，再扫描药包核对登记号，核对成功后确认发药 |
| 住院流程 | 药房验收 → 病区护理站逐包扫码接收 → 病区患者核对发药；增加独立病区接收页面 |
| 验收加载 | 不限制处方日期，不以“已打包”作为唯一验收前置条件，扫一条加载一条；拒绝重复验收及已发药回退 |
| 处方摘要 | 验收、发药均展示姓名、剂数、用法、处方号等原型字段；处方中药组成明细尚未提供接口数据 |
| 发药检索 | 姓名、登记号、处方号、住院号、床号，保留原型身份证号检索；点击搜索或回车才触发 |
| 默认列表 | 保留原型最近两天及两种自取方式；主动搜索可查全部日期的已验收、自取处方 |
| 发药前置 | 未验收、已退方、已撤回、非自取、跨医院、药包 / 患者登记号不一致时禁止发药 |
| 批次发药 | 普通处方直接按单批次处理；拆分处方按执行批次分别验收及发药，处方号有歧义时要求扫描具体批次药包码 |
| 操作记录 | 验收、病区接收、发药分别记录；展示操作人、时间、医院，成功后同步更新统计 |
| 重复提交 | 当前前端会话使用提交锁及状态检查，避免同一批次重复操作；多设备并发由真实后端实现 |
| HIS | 每个新操作产生本地模拟回传事件；真实实时回传需后端接入 |
| 短信 | 门诊验收后产生本地模拟取药通知事件；真实短信需网关及模板接入 |

## 待医院 / 业务确认

1. 两台 PDA 是否需要固定“验收机 / 发药机”角色。目前业务入口均可用，没有伪造生产角色权限。
2. 验收和发药是否都需要处方药味、克重等完整中药明细，还是仅验收时显示。
3. PDA 二维码真实内容：纯就诊号 / 处方号，还是结构化字段；拆分批次和每个药包的唯一标识规则。
4. 住院是否存在病区转运、接收交接人，以及一个执行批次多个独立物理药包的情况。目前演示一条批次对应一个药包；真实接口需给出 packageId 与 batchId 的关系。
5. 自取枚举是否最终确定为“配送自取 / 代煎自取”，窗口自取是否另有业务处理入口。
6. 最近两天是否仅作为默认查询，主动搜索历史处方是否允许。本项目采用默认两天、主动搜索不限日期。
7. 门诊独立 App 的 AppID、证书、PDA 型号及扫码 SDK；住院护理系统嵌入方式、单点登录及页面入口协议。
8. 门诊及住院医院 Wi-Fi 覆盖、内网 / 外网服务地址、HTTPS、网络隔离及断网策略。当前不允许以离线本地操作作为生产发药依据。
9. HIS 回传协议、超时 / 重试 / 对账要求及短信网关、患者手机号来源、短信模板和发送策略。
