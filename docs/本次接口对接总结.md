# 中药房 PDA 接口对接总结

日期：2026-11-18。依据附件《中药房PDA接口对接文档.md》v1.0，以及后续 `reportsharemanager-new` 提供的《登录接口对接说明.md》和 `src/utils/Secret/`。

## 本次变更

- 最新新增登录后医疗机构选择弹框：展示当前姓名、账号、用户编号和所选业务，调用 `POST /preInstitutionInfo/list` 每页 100 条依照返回页数加载，按 `jglx=1` 筛选医院并去重。下拉选择的 `jgdm`、`jgmc` 分别写入 `hospitalCode`、`hospitalName`；用户确认后才进入业务工作台，未选医院时不能发送后续业务请求。刷新待选择流程可恢复弹框，空列表/失败支持重试，不生成演示机构，不自动选中唯一医院。仅保留列表的名称、编码和展示标签，不保存机构敏感字段。
- 新增独立登录页面，沿用现有青绿色主色、浅灰背景、图标和表单样式。按用户最新要求仅保留账号密码登录，移除会话登录、产品标识输入、医院名称和医院编码输入，登录产品标识固定为数值 `6`。
- 关闭静态数据模式，业务数据和写入结果均来自接口。
- 业务鉴权同时携带 `Access-Token` 和 `WeAppAuthorization`，值均为原始会话令牌，不添加 Bearer。业务请求使用 POST JSON，只有 `code === 0` 才作为成功响应。未登录、HTTP 401/403、业务 403、未登录类 1000，以及顶层消息包含“重新登”“尚未登录”时清理当前登录并返回登录页。
- 登录改为 `POST /api/system/user`，采用 JSON-RPC 2.0 的 `Login`，`productId` 固定为 `6`。登录响应先处理 `error.message`，再检查 `result.sessionKey` 和用户资料，不使用业务接口的 `code === 0` 规则，也不再调用待验收接口代替登录。保存完整 `result`，将 `user.userName`、`user.userId` 映射为当前操作人；非空密码到期消息弹窗提示，原密码不写入本地存储。
- 门诊/住院业务仍独立选择，成功后进入对应业务工作台；病区配置仅住院时显示。业务参数 `mode` 不加入登录请求，也不从 `personType`、`orgType`、`corpId` 推断。
- 直接复制附件 `Secret/BigInt.js` 和 `Secret/RSA.js`，保留版权和相对导入。密码按附件公钥及 PKCS#1 v1.5 生成十六进制密文，多块空格分隔；没有替换为 Base64、MD5 或 RSA-OAEP。
- “我的”退出登录改为调用同一登录地址的 `Logout`，携带两个鉴权头；请求成功或失败都清理当前本地会话和业务缓存。
- 登录页不再采集医院名称和编码；业务医院上下文可由部署配置提供，缺失时由后端按单医院绑定规则识别。住院接收仍需病区编码，实际医院和病区授权由后端决定。
- 验收支持扫码定位后匹配待验收批次、逐包验收及逐条批量验收；不可验收原因使用服务端字段。
- 接入今日验收，工作台、验收页、验收明细均读取真实计数和逐批次记录。
- 病区接收页面改为真实接收操作，调用接收确认及今日接收接口；新增接收明细入口。
- 新增独立住院发药页面，扫码定位后结合待发药列表补全病区和处方信息，再确认发药；支持检索与逐条批量发药。
- 新增独立整单验收页面，按运单查询，支持整单验收和所选处方验收。所选处方按 `recordId` 去重提交，会验收这些处方在当前运单下的全部药包，确认弹窗已说明。
- 门诊保留就诊码识别、药包码核验、确认发药的双扫码流程。原有批量发药使用文档允许的直接 `/dispense/confirm`，不带双扫码凭证；这一路径不构成双扫码强闭环。
- 写入保留拆分批次及物流记录标识，重复发药、接收及整单验收按接口幂等字段提示；写操作遇到 6109 后刷新对应列表，不自动重试写入。
- 列表按服务端页数加载全部分页；今日记录使用服务端统计日期和时间，不按浏览器日期重新统计。
- 移除“最近两天”“配送自取”等缺少接口依据的筛选标签，改为真实的已验收未发药、自取说明；取药方式按文档 2/3/4/5 显示。

## 未使用接口及参数分支

附件中的 14 个接口全部已有页面调用，没有整条未使用的接口。以下分支没有使用：

| 未使用分支 | 原因及对应位置 |
| --- | --- |
| `/pharmacy/scan/resolve` 的 `VISIT`、`WRISTBAND`、`ORDER_NO` | 当前通用扫码入口扫描药包；门诊就诊码走专用 `visit/start`。附件说明 HIS 映射表尚无数据，没有新增腕带或订单号入口 |
| `/hospital-acceptance/confirm` 的单个 `logisticsRecordId` 定位 | 整单页按整单或所选处方验收；精确逐包操作由药包验收页的 `/acceptance/confirm` 承担 |
| `/pharmacy/ward-receive/confirm` 的 `scanCode` 解析分支 | 病区接收先定位和显示批次，再提交 `recordId`、`executionRecordId`，没有直接扫码即写入的入口 |
| 精确检索 `PICKUP_NO` | 当前检索入口延用姓名、登记号、处方号、证件号或住院号、床号，没有单独的取药号精确搜索控件 |
| 旧 `/prePrescriptionInfo/checkBatch`、`distributeBatch` | 未使用；附件明确说明旧接口不适用。现有批量操作逐条调用新确认接口 |
| 登录 JSON-RPC `ChangePassword` | 属于附件可选功能；本次登录页范围未新增修改密码页面，密码到期信息已提示并保存 |
| `SwitchLogin`、URL 查询参数 `SessionKey` 自动登录 | 按用户要求取消会话登录，页面及服务均不再使用 `SwitchLogin` |

## 配置与执行边界

- `VITE_PRESCRIPTION_API_BASE`：默认 `/api/prescription`，支持完整后端地址。
- 医院下拉框请求地址已按用户最新要求改为 `POST /api2/axd/preInstitutionInfo/list`，开发代理与登录共用 `VITE_BAAS_PROXY_TARGET`，使用两个 Token 鉴权头；机构接口无需医院编码或业务 `mode`。原 14 个业务接口地址保持不变。
- 开发服务代理 `/api/prescription` 至 `VITE_PRESCRIPTION_PROXY_TARGET`，默认 `http://127.0.0.1:8082`；生产部署需要配置网关转发或后端 CORS。
- `VITE_BAAS_USER_API`：默认 `/api/system/user`；该路径的开发代理目标通过 `VITE_BAAS_PROXY_TARGET` 设置，默认附件的 `https://smadev.simmed.cn`。没有增加 `/api2` 或前端部署目录前缀。
- 登录 `productId` 按用户要求固定为数值 `6`，不再读取 `VITE_BAAS_PRODUCT_ID`，登录页不展示该字段。
- 登录请求超时 60000 毫秒，业务请求仍为 20000 毫秒。没有增加刷新令牌接口，也没有将参考项目的 165 分钟本地缓存期限当作服务端有效期。
- `.env.example` 保留医院、病区部署默认值；病区可在登录页填写，医院信息不再提供登录页输入。
- 会话存储键：`pharmacy-pda-session`。Token 字段为 `token`，值为登录响应的 `sessionKey`；原始响应保存在 `loginInfo`。请求头为 `Access-Token`、`WeAppAuthorization`，不使用旧 `Authorization`。
- 登录上下文可由宿主通过 `uni.setStorageSync('pharmacy-pda-session', { token, hospitalCode, hospitalName, wardCode, wardName, operatorId, operatorName, department })` 写入。
- 本次为前端代码接入，没有使用真实账号、密码或扫码样本，未宣称真实账号登录和医院环境联调通过。登录服务和业务服务仍需共享可识别的会话存储。
- 按用户要求未执行打包、导出、自动化测试、页面验证或真实业务写入验证。`standalone/pharmacy-pda.html` 未重新生成，仍是旧离线演示。
