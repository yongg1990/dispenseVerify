### 关键发现（评审核心）
- **src 实际跑静态数据**：`src/services/data-source.js` 仅 `export const useStaticData = true`，prescription.js 第 33 行直接返回 staticPrescription，真实 HTTP 分支不执行。README 第 3 行"已改真实接口"与代码不符，以代码为准。
- **standalone/pharmacy-pda.html 与 src 同源**：脚本 scripts/export-single-html.mjs 从当前 8 页编译导出，非旧版，无独有内容。README 说它"未重新导出"也不准。
- **前后端接口不匹配（最大风险）**：前端调 12 个 `/pharmacy/*` 接口，后端（prescription_landa 的 PharmacyController）实测只有 6 个。缺的 6 个：`acceptance/today`、`outpatient/visit/start`、`outpatient/prescription/verify`（门诊双扫码）、`ward-receive/page|confirm|today`（住院病区接收）。即前端两条主流程逻辑写得最完整，但后端没有对应接口。
- **静态数据缺全部拦截样本**：README 声称的 PKG-CANCELLED/WITHDRAWN/FOREIGN 在 static-prescription.js 里搜不到；statusLabels 定义了 cancelled/withdrawn 但无数据触发。requiresHISMapping、非自取、登记号不一致也无样本。
- 演示数据 14 条处方（门诊 8 / 住院 6），时间全为当天；无历史日期，导致"最近两天/全部日期"筛选无意义、明细页"全部"按钮禁用。
- 死控件：dispense 页 4 个 filter-chip 是 `<text>` 点不动；RecordList"全部"按钮 disabled。
- **名实不符**：ward-receive 页叫"接收"但实际调 `dispensePackage()` 发药，`receivePackage()` 是死代码没页面调用。
- profile 页无 README 声称的 HIS/短信模拟事件，仅状态文案。
- 语义/契约不一致：门诊批量发药静态放行真实拦截；短信勾选文档说禁用但代码两种模式都能勾；审计时间用客户端 new Date()；静态数据有 ingredients/acceptedByName 但后端 map() 不返回。
