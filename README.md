# 中药房 PDA 工作台

> 接口版本说明：`src` 已改为调用真实业务接口，不再读取演示处方或本地操作记录。部署配置、页面接口映射、未使用接口和缺失契约见 [接口对接交接文档](docs/接口对接交接文档.md)。下方的演示数据和旧边界仅适用于未重新导出的 `standalone/pharmacy-pda.html`；本次未打包、导出、测试或进行真实环境联调。

基于 uni-app + Vue 3 + Vite 的移动端项目，包含 H5 演示和 App 扫码适配。以 HTML 原型作为页面结构参考，以《控制台.txt》的业务沟通要求为优先规则。

## 启动

```sh
npm install
npm run dev:h5
```

默认访问 http://localhost:5173 。同一局域网移动设备可通过开发机 IP 和 5173 端口访问，需允许防火墙入站。

App 开发可使用 HBuilderX 导入本目录，在完善 `src/manifest.json` 的 AppID、证书及 Android 配置后运行。原生端调用 `uni.scanCode`，PDA 若使用厂商广播扫码服务，需按实际硬件 SDK 增加适配；键盘输出型扫码枪可使用输入框。

## 单文件 HTML

直接打开 `standalone/pharmacy-pda.html` 即可离线演示，无需启动服务或联网。页面、Vue 运行时、样式和图标均内嵌，扫码使用模拟二维码选择器。浏览器须允许本地存储才能保存操作；数据与原 H5 项目隔离，不会互相覆盖，也不会跨浏览器或设备同步。

修改现有页面后，可重新导出：

```sh
npm run export:html
```

导出脚本复用 `src/pages.json` 中各自独立的页面组件及业务逻辑，仅在导出时适配浏览器标签、导航和存储。现有 `src`、H5 / App 开发入口和发布配置保持不变；此 HTML 是独立演示产物，不替代后续正式打包发布。

## 页面

- 工作台：门诊 / 住院切换、四个业务入口、统计及最近操作。
- 药包验收：不预加载处方，扫码或输入编号后逐条加载；查看处方摘要后验收。
- 患者发药：患者识别、处方检索、药包核对、二次确认。
- 验收明细：验收时间、医院、操作人、执行批次和检索。
- 发药明细：发药时间、医院、操作人及验收时间。
- 病区接收：住院药房验收后，护理站逐包扫描接收。
- 我的：模拟人员信息、环境说明、HIS / 短信模拟事件。

每个菜单均有独立页面文件；仅通用 UI 和业务规则复用。

## 演示数据

H5 的扫描按钮弹出明确标识的模拟二维码选项，不调用摄像头。App 端调用原生扫码。数据保存在当前浏览器 / 设备的本地存储中，不会跨设备同步。

| 场景 | 示例 |
| --- | --- |
| 门诊患者 | `JZ-1007`，陈*怡，登记号 `DJ-4106` |
| 门诊拆分批次 01 | `PKG-M7-01`，已验收 |
| 门诊拆分批次 02 | `PKG-M7-02`，先扫码验收，再发药 |
| 门诊普通待验收 | `PKG-M6-01`，患者就诊号 `JZ-1006` |
| 历史处方验收 | `PKG-M4-01`，超过两天仍可验收；发药时主动搜索 `夏` 或 `DJ-4103` |
| 住院患者 | `ZY-1013`，刘*芳，药包 `PKG-Z7-01` |
| 完整住院流程 | `PKG-Z6-01`：药房验收 → 病区接收 → 患者 `ZY-1012` 识别 → 发药 |
| 拦截演示 | `PKG-CANCELLED` 已退方，`PKG-WITHDRAWN` 已撤回，`PKG-FOREIGN` 其他医院 |

## 当前边界

这是可交互的前端项目，不是已联通医院生产系统的成品。操作人和医院为演示身份，客户端时间为演示时间；HIS 回传和短信只生成模拟事件，没有向外部系统发送数据。

同一页面的重复点击由状态检查及提交锁阻止；跨浏览器、跨 PDA 的并发幂等、真实权限和跨医院隔离必须由后端事务、唯一约束及认证上下文保障，不能由前端本地存储保障。

需求合并和待确认项见 [需求汇总](docs/requirements.md)，真实系统接入约定见 [接口联调说明](docs/integration.md)。本次未执行生产打包和自动化测试。
